# 作業ノート

[Slidev原稿](slidev/slides.md)と台本（各スライドの発表者ノート）を編集するときの約束と手順。発表の筋と見せ方は[発表案](../biangbiangcon-open-character-data.md)を正本とする。

## 台本を書くとき

- 異体字やそっくりな字の組は、口頭で並べても聞き分けられない。円・圓・圆、仏・佛、乾と干、復・複・覆と复はどれも同じ音になり、䍏や玊のように読めない字もある。
  - 組を言う必要があるときは「新字体の円」「旧字体の圓」「簡体字の圆」のように字の種類を添える。
  - 「転覆の覆」「復活の復」「複数の複」のように、その字を使う語で言い分ける方法もある。
  - それ以外は片方の字だけを言い（「乾や予のように」「冊、央、玉、辛のように」）、組は画面で見せる。
- 「正確な」「正しい」で言い切らない。対応のさせ方、画数の出典、新字体・簡体字の範囲のように決め方が複数ある前提は、「一つの決め方」として示す。
- ①の問いは、もとの疑問に近い言い方「新字体より画数が多い簡体字は？」で見せる。計算できる形に直した「常用漢字より画数が多い規範字は？」とは意図して使い分けている（SQLは後者を計算する）。二つを混ぜた「常用漢字より画数が多い簡体字」にしない。
- 発表者が手で直した台本の言い回しに合わせる。台本を書き換えるときは、直前の版を読んでから直す。
- 読み上げ文を変えたら、実際に読みながらスライドの時間の目安を見直す。

## データに印や分類を付けるとき

- 印や凡例は、資料に載っているかどうかで定義する（例：「常用漢字表に康熙字典体なし」「規範字表に繁体字なし」）。「旧字体」「伝承字」「簡体字」のような意味の語で言い切ると、定義に注釈が要る。意味の説明は読み上げとノートに置く。
- 「字形」と「字体」を使い分ける。日本の用語では、Unicodeで包摂（unify）される違いが「字形」、包摂されない違いが「字体」。符号位置で同じかどうかを判定している場面は「同じ文字」と言い、「同じ字形」と言わない。ただし③の「kZVariantのない字形違い」（緒緖・謠謡）は「字形違い」でよい。Z-variantは同じ字体にあたる関係で、本来は統合できるのに原規格分離などのルールや収録時の漏れで別の符号位置になった組の話だから。
- 資料ごとに線の引き方が違う例（叠と疊、搖と摇、佛と彿・髴）は、ノートの `***` の後に質疑用として残す。未確認の経緯は未確認と書く。

## スライドを確かめる

- 1枚だけPNGに書き出して見る。Edgeを使うのでPlaywrightのブラウザは要らない。

  ```powershell
  node node_modules/@slidev/cli/bin/slidev.mjs export slides.md --format png --range 10 --output $env:TEMP\s10 --executable-path "C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe"
  ```

- [style.css](slidev/style.css)に新しいクラスを足す前に、同じ名前がないか検索する（`.join` は①のSQLの色分けで使っている）。
- スライドを足したり削ったりすると、発表案のスライド番号と短縮方針の表がずれる。
